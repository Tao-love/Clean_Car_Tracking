# 1-3：MSPM0G3507 循迹小车无线自动整定批准方案

日期：2026-07-20

状态：已批准，作为后续实现、测试和验收的当前唯一方案依据。

适用硬件：MSPM0G3507、两只 MG310 AB 相编码器电机、TB6612FNG、八路数字灰度、JDY-31 SPP、XDS110。

## 1. 文档地位与合并原则

本文整合了初始方案 `2026-07-20-wireless-autotune-design.md`、中间方案 `1-2.md` 以及之后的硬件和软件核查结果。后续实现以本文为准；旧文档仅保留讨论历史，不再作为实施依据。

本文已经消除以下冲突：

- TB6612FNG 的 `STBY` 在现有 PCB 上固定接 5 V，不能由 MCU 拉低，不能再作为急停或 Flash 写入期间的硬件禁能手段。
- 每组参数的单次试验固定运行 5 秒，由 MSPM0 本地计时和停车。
- 电池电压采样和电流检测均列为后加项，首版不采购、不接线、不写相应驱动。
- 首版运行时参数先保存在 RAM；只有最终最优参数经明确提交命令确认后才写入 Flash，不在每次自动试验中写 Flash。
- VOFA+ 用于观察，不直接占用 Python 正在使用的蓝牙 COM 口，也不参与自动寻优决策。

批准本文代表总体架构、安全边界、模块划分和实施顺序已经确定。赛道尺寸、轮径、编码器每圈计数等现场数据属于标定输入，不再视为架构未决项。

## 2. 项目目标

构建一套无线循迹自动整定系统：电脑端 Python 程序通过 JDY-31 向 MSPM0 下发候选控制参数；MSPM0 在本地完成 100 Hz 实时控制、5 秒试验、安全判断和统计；Python 接收结果、评分并选择下一组参数。

系统必须满足：

- 电脑或蓝牙卡顿时，安全停车不依赖 Python 再发送停止命令。
- 每次试验到 5 秒必须由 MCU 自动停车。
- 参数可以在运行前无线修改，不需要每组参数都重新编译和烧录。
- 自动整定失败时保留并回滚到最后一组已验证安全参数。
- 首版不依赖摄像头、Wi-Fi、模拟灰度、电池 ADC 或电流检测模块。
- 赛道直角、环形路线和更高速度策略在基础系统稳定后通过配置和状态机扩展，不推翻本文架构。

- 赛道存在直角。

## 4. 首版物理连接与采购结论

### 4.1 JDY-31 接线

| PCB / MSPM0 | JDY-31 | 说明 |
| --- | --- | --- |
| `TX1 / PA8` | `RXD` | MCU 发送接蓝牙接收 |
| `RX1 / PA9` | `TXD` | MCU 接收接蓝牙发送 |
| `GND` | `GND` | 必须共地 |
| 稳定 `5V` | `VCC` | 不得接 `VBAT_IN` |

`EN` 与 `STATE` 首版不接。UART 信号必须为 3.3 V 逻辑电平，不允许把外部 5 V UART 信号直接送入 MSPM0。

首次联调统一使用 9600 baud，因为 JDY-31 常见出厂值为 9600，而现有 MCU 配置的 115200 尚未与模块匹配。链路通过后仍先保持 9600；只有确认模块 AT 配置方法和高速链路稳定性后，才允许把双方一起改为 115200。

### 4.2 XDS110

XDS110 只在烧录新固件或定位程序问题时连接。正常蓝牙调参、VOFA+ 观察和小车运行不需要 XDS110。运行时断点会暂停 MCU，因此不得把带断点的调试作为正常安全试验方式。

### 4.3 当前采购结论

首版不需要新增硬件采购。现有器件和接线足以开始通信、控制和自动整定实现。

以下内容明确后加，目前不采购、不接线、不进入首版固件：

- 22 kOhm、10 kOhm、100 nF 组成的电池电压采样电路；以后需要时可从 `VBAT_IN` 分压到空闲 ADC 脚 `PA25`。
- INA219、分流电阻或电流检测放大器。
- 独立外部电源切断开关。

测试时必须保证电池插头可快速拔除；在 `STBY` 固定高电平的 PCB 上，拔除电机电源才是最终物理断电手段。

## 5. 总体架构与数据所有权

通信路径：

`Python 自动整定程序 -> Windows 蓝牙 COM -> JDY-31 -> MSPM0 UART`

回传路径：

`MSPM0 -> JDY-31 -> Python -> 日志 / 实时曲线 / VOFA+ 转发`

职责边界：

1. MSPM0 固件负责灰度采样、编码器速度、双闭环、电机输出、5 秒计时、本地故障停车、试验统计和最终参数 Flash 保存。
2. Python 独占 JDY-31 对应的 COM 口，负责协议交互、心跳、候选参数生成、试验编排、评分、失败回滚、日志和报告。
3. VOFA+ 只观察 Python 转发的数据，不负责发送控制命令、不计算最终评分、不与 Python 抢占同一个 COM 口。VOFA+ 转发失败不得中断 MCU 控制或自动整定。

硬实时任务全部留在 MCU；无线链路只用于低速命令与遥测。

## 6. 100 Hz 调度与中断边界

- 10 ms 定时器产生单调递增 `controlTick`，不能继续只使用会合并多个周期的布尔标志。
- 主循环根据 tick 执行有界的传感器、控制、安全和统计任务，并记录漏执行或超期次数。
- UART 接收中断只把字节写入 RX 环形缓冲区；UART 发送中断只从 TX 环形缓冲区取字节，不在中断中解析帧或计算 CRC。
- 编码器中断只更新计数和方向所需的最小状态。
- 协议解析、统计汇总、文本日志和 Flash 操作不得在控制中断中执行。
- 遥测发送必须非阻塞；TX 队列拥塞时优先丢弃低优先级实时遥测，不能阻塞控制和可靠汇总。

## 7. 双闭环控制

### 7.1 左右轮速度 PI 内环

左右轮分别计算：

`PWM = feedforward + Kp_speed * speed_error + Ki_speed * speed_integral`

要求：

- 每 10 ms 更新一次。
- 左右轮允许独立 `Kp`、`Ki` 和前馈参数，以补偿电机差异。
- 具备 PWM 限幅、积分限幅和条件积分抗饱和。
- 目标速度为零、试验结束或进入故障时清空积分并执行统一停车函数。
- 首版速度单位使用“每 10 ms 编码器计数”；轮径和每圈计数确认后可在上位机换算为物理速度，不改变闭环结构。

### 7.2 八路灰度循迹 PD 外环

保持已有加权中心算法：

`error = sum(sensor[i] * weight[i]) / sum(sensor[i])`

误差有效范围为 `-3500` 至 `3500`。外环计算：

`deltaSpeed = Kp_line * error + Kd_line * filteredDerivative`

左右目标速度为：

`leftTarget = baseSpeed - deltaSpeed`

`rightTarget = baseSpeed + deltaSpeed`

要求：

- 首版巡线只使用 PD，`Ki_line` 固定为零。
- D 项使用一阶低通后的误差差分，并限制单周期最大值，避免数字位图跳变产生尖峰。
- 基础速度、差速修正、左右目标速度和最终 PWM 分层限幅，所有饱和状态进入统计。
- 八路均未触发时不继续无限沿用旧误差，而是进入丢线计时。
- 多数或全部传感器触发时记录特殊图案事件；直角或特殊标志的具体解释在赛道扩展阶段实现。
- MCU 内部控制参数使用明确的定点缩放，增益统一采用有符号 Q16.16，协议与日志同时记录缩放规则。

### 7.3 参数原子切换

- `pendingParams` 保存协议已完整接收并通过范围校验的候选参数。
- `activeParams` 保存当前控制周期实际使用的参数。
- 只在非 RUNNING 状态下，于 10 ms 控制边界把整组 `pendingParams` 一次性复制为 `activeParams`。
- 每次成功应用参数后递增 `paramVersion`，ACK、遥测和汇总均携带该版本。
- RUNNING 期间锁定参数；任何修改请求返回“试验进行中”，不能让同一组 5 秒数据混入两套参数。

## 8. 统一停车动作与安全边界

由于 `STBY` 固定高电平，统一软件停车动作必须同时完成：

1. 把 `PWMA`、`PWMB` 比较值立即写为 0。
2. 把 `AIN1`、`AIN2`、`BIN1`、`BIN2` 全部写低。
3. 清空左右速度 PI 积分和目标速度。
4. 锁存停止原因、故障码和发生时的控制 tick。

该函数用于上电初始化、试验开始前、5 秒到期、人工停止、通信超时、丢线、堵转、参数异常和控制超期，避免不同路径产生不同停车行为。

批准的首版安全阈值：

- 心跳：Python 每 100 ms 发送一次；RUNNING 状态连续 400 ms 没收到完整且 CRC 正确的合法帧时，本地停车并锁存 `COMM_TIMEOUT`。
- 堵转：当某轮 PWM 绝对值高于初始安全阈值、但编码器速度连续 300 ms 低于速度阈值时，本地停车并锁存左右轮对应故障。PWM 和速度数值由车轮离地台架测试写入受限配置。
- 丢线：八路全部未触发连续 150 ms 时，本地停车并锁存 `LINE_LOST`。后续若赛道直角验证表明需要更短的受限找线窗口，可增加专用状态，但自动整定首版默认先停车。
- 控制超期：连续漏执行达到受限阈值时停车并锁存 `CONTROL_OVERRUN`。
- 参数异常：CRC 正确但参数越界、非有限定点值、版本不兼容或内部状态不一致时拒绝启动；运行中发现内部异常则停车。

首次电机试验必须车轮悬空；首次实地循迹从不高于满量程 25% 的 PWM 上限开始。软件停车不能等同于硬件切断，测试人员必须能立即拔除电池。

## 9. 五秒试验状态机

状态定义：

- `BOOT_SAFE`：上电后最早执行统一停车和自检。
- `IDLE`：可通信、设置参数和读取状态，电机保持停止。
- `ARMED`：参数、会话和安全条件有效，等待启动命令。
- `RUNNING`：执行 100 Hz 双闭环、500 tick 计时和本地统计。
- `FINISHED`：已停车，保存本次汇总并等待可靠发送完成。
- `FAULT`：已停车并锁存故障，必须确认条件恢复后接受 `CLEAR_FAULT`。
- `FLASH_WRITE`：只从 IDLE 进入，电机保持统一停车状态，完成后回到 IDLE。

单次试验流程：

1. Python 发送候选参数及命令序号。
2. MCU 校验参数，在控制边界应用并返回 `paramVersion`。
3. Python 收到匹配 ACK 后发送 `ARM`，再发送 `START_TRIAL`。
4. MCU 再次执行停车、清空统计和控制积分，然后进入 RUNNING。
5. MCU 本地累计 `500 × 10 ms`；第 500 个 tick 到达时立即执行统一停车。
6. MCU 生成并可靠发送 `TRIAL_SUMMARY`，Python 评分后才选择下一组参数。
7. 通信超时、持续丢线、堵转、控制超期、参数异常或人工停止可以在 5 秒前结束试验。

每一次 trial 都只能运行最多 5 秒。同一参数允许按配置执行多次独立 5 秒试验并汇总评分，用于降低不同赛道位置带来的比较偏差；首轮联调默认每组一次，具体赛道确认后再增加重复次数。

成功试验结束后，Python 可以在安全停顿和状态确认后从当前位置继续下一组；发生故障或车辆离线时必须暂停自动序列，等待人工把车恢复到安全位置。

## 10. 通信协议

首版使用带长度、序号和 CRC 的小端二进制帧：

| 字段 | 长度 | 说明 |
| --- | ---: | --- |
| Magic | 2 B | 固定 `0xA5 0x5A` |
| Protocol version | 1 B | 首版为 1 |
| Message type | 1 B | 命令、应答、遥测或事件 |
| Flags | 1 B | ACK 请求、错误和优先级标志 |
| Sequence | 2 B | 16 位递增命令序号 |
| Payload length | 2 B | 载荷长度，最大 128 B |
| Payload | N B | 按消息类型定义 |
| CRC16 | 2 B | CRC-16/CCITT-FALSE，覆盖 Version 至 Payload |

首版命令：

- `HELLO`：交换协议版本、固件版本、设备能力和会话 ID。
- `HEARTBEAT`：维持 RUNNING 会话。
- `SET_PARAMS`：写入并申请应用 RAM 候选参数。
- `GET_STATUS`：读取状态、故障、参数版本和最近停止原因。
- `ARM`：确认当前会话和安全条件。
- `START_TRIAL`：开始一次本地 5 秒试验。
- `ABORT_TRIAL`：人工提前停止。
- `CLEAR_FAULT`：危险条件恢复后清除可恢复故障，不自动重新启动。
- `SET_TELEMETRY`：设置实时遥测开关和频率。
- `COMMIT_PARAMS`：在 IDLE 中把明确选中的最优参数写入 Flash。

可靠性规则：

- 只有完整、长度合法且 CRC 正确的帧才能执行命令并刷新心跳时间。
- 改变状态的命令按 `Sequence + Session ID` 去重；重复帧返回原 ACK，但不重复启动试验或写 Flash。
- `SET_PARAMS` 未收到匹配 ACK 时不得 ARM；ARM 未收到匹配 ACK 时不得 START。
- 串口粘包、截断、噪声和 CRC 错误只触发重新同步，不执行部分命令。
- 未知版本、未知消息和越界参数返回 NACK 及明确原因码。
- 9600 baud 联调阶段实时遥测默认 10 Hz；验证链路余量后可提高到 20 Hz，本地控制始终为 100 Hz。

## 11. 本地统计与遥测

每个 10 ms 样本在 MCU 本地累计：

- 样本数和有效运行时间。
- 绝对误差和、平方误差和、最大绝对误差。
- 固定误差直方图，用于近似 P95。
- 丢线样本数和最长连续丢线时间。
- 左右目标速度、实际速度、PWM 的和与最大值。
- PWM 和目标速度饱和样本数。
- 带死区的误差符号翻转次数，用于估算振荡。
- 左右编码器累计计数。
- 参数版本、停止原因、故障码和控制超期次数。

500 个样本的和与平方和使用 64 位整数并带饱和保护。实时遥测丢失不影响本地累计；试验结束以可靠的 `TRIAL_SUMMARY` 为最终评分数据源。

实时遥测至少包含：时间戳、八位灰度位图、位置误差、左右目标速度、左右实际速度、左右 PWM、状态、故障和参数版本。

电池电压、电流和 MPU6050 数据不进入首版必需评分项；其中 MPU6050 可在不影响控制带宽时作为诊断通道后加。

## 12. Python 自动整定程序

Python 程序按职责拆分：

- 串口模块：发现和打开 JDY-31 的 Windows COM 口。
- 协议模块：帧编解码、CRC、Sequence、ACK/NACK、超时和有限重试。
- 会话模块：HELLO、心跳、状态镜像、ARM、START、ABORT 和故障恢复编排。
- 试验管理模块：下发候选、等待 5 秒本地试验、接收汇总、失败暂停和安全回滚。
- 评分模块：只用保存的配置和汇总数据产生可复现分数。
- 优化模块：按阶段和硬边界选择下一组参数，不生成超出安全范围的候选。
- 日志模块：记录原始帧、解码数据、参数、固件版本、协议版本、评分配置和停止原因。
- 可视化模块：Python 实时曲线和可选 VOFA+ 本机转发；失败不影响自动整定。

当前电脑环境已确认：

- CCS、MSPM0 SDK 2.11.00.07 和 SysConfig 已安装。

## 13. 评分与自动寻优

发生通信超时、堵转、长时间丢线、控制超期或参数异常的候选直接判为失败，并施加高于任何正常分数差异的失败惩罚。

正常试验按“越低越好”评分：

`J = w1*MAE + w2*RMSE + w3*P95 + w4*lostRatio + w5*saturationRatio + w6*oscillationRate - w7*meanSpeed + failurePenalty`

各项在 Python 配置中按固定安全范围归一化；权重、归一化范围和重复试验次数随日志保存，保证结果可以离线复算。速度奖励不得抵消安全失败惩罚。

寻优分四阶段：

1. 电机辨识：车轮悬空，逐级增加受限 PWM，测启动阈值、左右差异和速度响应。
2. 速度 PI：使用小幅目标速度阶跃，先调比例，再调积分与前馈；左右轮分别验证。
3. 低速巡线 PD：`Ki_line = 0`，先在安全范围搜索 `Kp_line`，再增加 `Kd_line` 抑制摆动。
4. 速度爬升：只从已验证安全参数逐级提高基础速度，每级进行局部搜索并保留上一组安全回滚点。

首版优化器使用有边界的网格搜索与坐标搜索。它行为可解释、容易回放并能严格执行安全范围；不把随机搜索、Optuna、SciPy 或贝叶斯优化作为首版依赖。

## 14. Flash 最优参数记录

自动试验过程中只修改 RAM，不为每个候选擦写 Flash。Python 确认最优参数后，只有显式发送 `COMMIT_PARAMS` 才允许保存。

保存规则：

- 只在 IDLE 状态接受命令。
- 写入前执行统一停车，确认两路 PWM 为 0、四个方向脚为低；由于 STBY 固定高，不声称实现硬件禁能。
- 使用两个 Flash 参数槽轮换写入；记录包含 Magic、结构版本、递增 generation、参数长度和 CRC。
- 写入新槽并读回校验成功后才把它视为最新记录。
- 上电选择 CRC 正确且 generation 最大的记录；两槽均无效时加载保守默认参数并保持 IDLE。
- Flash 操作不在 ISR 中执行；写入期间不允许 ARM 或 START。
- 不自动反复保存同一参数版本，降低无意义擦写。

## 15. 代码模块化与中文注释规范

后续任何实现必须遵守：

- 所有人工编写的注释使用清晰中文，说明意图、单位、边界和硬件影响，不能只复述代码。
- 每个 `.c/.h` 文件开头写明模块职责、依赖、运行上下文、数据单位、硬件副作用和故障输出。
- 每个对外函数说明用途、输入、输出、前置条件、副作用以及是否允许在中断调用。
- 每次调用 TI DriverLib 函数时，在上方用中文说明它改变的硬件状态和调用原因，使不了解库函数的人也能读懂。
- UART、协议、状态机、安全、控制、统计、Flash 各自独立；UART 只搬运字节，协议只处理帧，安全模块统一判定和停车，控制模块只计算控制量。
- 环形缓冲区、CRC、状态转换、PID 限幅、抗积分饱和、丢线和堵转判断必须注明中文流程及阈值单位。

AI 新增代码必须有可检索标记：

- C/C++ 成块新增代码前后使用 `// ----- AI`。
- Python 成块新增代码前后使用 `# ----- AI`。
- 不适合独立分隔时，在合法的行尾注释中以 `(AI--)` 开头说明，例如 `foo(); // (AI--) 初始化通信状态`。
- SysConfig 生成文件不手工插入标记；标记写在可维护的 `.syscfg` 配置或其相邻人工代码中，避免重新生成时丢失。

## 17. 验收标准

- 上电初始化首先把两路 PWM 设为 0、四个方向脚设为低；不虚构 STBY 可控能力。
- 任一正常试验最多运行 500 个 10 ms tick，到时无需 Python 停止命令即可停车。
- RUNNING 时断开蓝牙，最迟 400 ms 内两路 PWM 为 0且四个方向脚为低，并锁存通信故障。
- 高 PWM、低编码器速度持续 300 ms 能在 MCU 本地停车并报告对应车轮。
- 八路全未触发持续 150 ms 能在 MCU 本地停车并报告丢线。
- SET_PARAMS 未得到匹配版本 ACK 时不能启动；RUNNING 中不能替换参数。
- 重复 START 序号不会重复启动或重置统计。
- 随机串口噪声、CRC 错误、粘包和截断帧不会执行命令。
- 关闭实时遥测或使其拥塞，不影响 100 Hz 控制、5 秒停车和本地统计。
- 每次试验都留下参数版本、固件与协议版本、统计汇总、评分配置和停止原因。
- 失败候选不会成为最优参数；优化器始终保留最后一组安全回滚点。
- Flash 仅在 IDLE 且统一停车完成后显式写入；模拟无效记录时能回退到上一有效槽或安全默认值。
- VOFA+ 未启动或转发失败时，自动整定仍可继续。
