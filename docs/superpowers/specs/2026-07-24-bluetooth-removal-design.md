# 蓝牙路径剥离设计

## 目标

从 `USB_nobluetooth` 移除 JDY-31 蓝牙自动调参路径，同时保留 UART1 的硬件配置作为 3.3 V USB-TTL 回显接口，并保持现有手动 KEY1 控制、电机、编码器、灰度、循线及安全停车功能。

## 保留范围

- SysConfig 中的 UART1、PA8（TX1）、PA9（RX1）、9600 8N1 和 RX 中断。
- UART1 的非阻塞 FIFO/环形缓冲传输能力，改为服务 USB-TTL 回显。
- KEY1 启动、100 Hz 控制周期、最长 5 秒运行、丢线、堵转、控制超期和统一停车。
- `ControlParams` 与 Flash 已保存参数的读取布局；本轮不重排持久化数据，避免旧参数记录失效。

## 删除范围及顺序

### 1. MCU 蓝牙控制层

删除二进制协议帧、Session/Sequence、心跳、远程参数写入、远程试验启动/停止、遥测、汇总和蓝牙启动来源。主循环改为在不影响控制节拍的前提下把收到的 UART 字节原样写回。

影响：Python/JDY-31 无法再启动、停止、清故障、调参或提交 Flash；蓝牙专用的 400 ms 通信超时也随之移除。KEY1 手动启动和其他安全联锁保留。

### 2. PC 自动调参层

删除 `python/autotune/`、对应示例配置、依赖声明及 Python 自动调参测试。

影响：不再提供 COM 自动调参、评分、日志、VOFA+ 转发和参数 Flash 提交命令。

### 3. 文档与配置清理

删除项目内 JDY-31、蓝牙协议、自动调参和蓝牙验收文档；把 UART 相关注释和 README 改为 USB-TTL 回显连接说明。

影响：仓库不再保留蓝牙操作入口或协议参考。用户提供的 Obsidian 外部文档不作修改。

### 4. 残留检查

只进行静态引用检查，不编译、链接、运行单元测试、验证脚本或烧录。

影响：可发现遗留的蓝牙名称或无效包含关系，但不能代替用户在实物上的烧录与串口回显验证。

## 连接与回显行为

使用 PCB 的 `USART1` 扩展口：USB-TTL TXD 接 RX1/PA9，RXD 接 TX1/PA8，GND 接 GND，不接 5 V。USB-TTL 必须为 3.3 V 逻辑电平。

固件收到的每一个 UART 字节立即经既有非阻塞发送队列回传；它不解释文本或二进制内容，不启动电机，不改变控制参数。

## 错误处理和验证

USB-TTL 未接、接线错误、端口被占用或波特率不一致时，固件不会因此启动电机或停车。用户烧录后，以 9600 8N1 将 `ping` 发送到转接器对应 COM 口，并使用 Python 串口工具确认收到同样的字节序列。

本次修改不在本机编译或运行测试；实际烧录和回显由用户执行。
