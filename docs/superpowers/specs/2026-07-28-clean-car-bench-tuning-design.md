# Clean_Car 独立轮速台架调参设计

## 目标

为 Clean_Car 增加与普通循线运行完全隔离的 10 秒双轮速度台架，使上位机速度阶段始终以目标速度 5 自动调参；TUI 可在台架运行期间临时阶跃目标，并可由用户确认后导出历史最佳六项参数并安全退出。

## 固件边界

`LineRun` 保留普通 KEY1 与 `RUN` 的既有循线、灰度和 MPU 路径。新增 bench 模式只调用编码器更新、两个速度 PI 和电机输出，启动时把两个目标复位为 5。`BENCHTARGET` 只在 bench 活跃时记录一个已验证的共同目标，控制 tick 读取该值，因此 ACK 之后在下一 tick 同时切换左右目标。停止、普通启动和新的 bench 启动均恢复默认值 5。遥测复用现有 21 列字段；line error 在台架中为 0。

UART 仍使用受 XOR 保护的请求帧与 ACK/ERR 回包。`BENCH` 仅在空闲时被接受；`BENCHTARGET` 仅在 bench 运行时且 VALUE 为 1 到 8 时被接受。普通 RUN、SETALL 和 STATUS 的解析及行为不变。

## 上位机边界

Clean_Car speed 阶段首轮先通过 SETALL 的 ACK 下发左右 `P=12, I=0, D=0`，每个自动采样轮以 `BENCH` 开始。保存整个轮次的双轮目标/速度/PWM 数据；专用评分对每一轮单独计算误差、超调、振荡、暖机后连续 100 ms 的 |PWM|>=550 和稳态反向。任一轮拒绝即回退到历史最佳，且不会计入连续合格轮数。速度阶段固定 D=0，P 范围 0--60，I 范围 0--0.05，单轮增幅不超过 1.5 倍；三轮双轮合格才产生自动收敛导出。

人工 TUI 的 `t` 改为只向活跃台架发送 BENCHTARGET；人工阶跃数据带观察标记，不影响自动评分、历史最佳和导出。`s` 显示确认对话框；确认后停止工作线程，尝试用历史最佳的左右 PI 与当前另一阶段完整快照导出 JSON/TXT，并把 `completed_reason` 写为 `manual_export_best`。它不向板子写参数，且无完整六项参数时不创建报告、显示原因后同样退出。

## 验证

固件 C 主机测试覆盖命令边界、默认 target、下一个 tick 同步更新和普通 RUN 未改变。Python 测试覆盖命令构造、首轮初始化、双轮评分/回退/三轮门槛、人工阶跃排除、手动导出和 TUI 确认/取消/线程状态。最后运行上位机完整 `pytest -q`、固件已有离线验证脚本和 Debug 强制全量编译；不烧录或驱动电机。
