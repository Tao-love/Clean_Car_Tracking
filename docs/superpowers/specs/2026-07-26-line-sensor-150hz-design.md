# 150 Hz 灰度与控制周期改造

## 目标

将八路数字灰度、循线 PD 和双轮速度 PI 的共同控制周期从 10 ms（100 Hz）提高到约 6.667 ms（150 Hz）。提高实际修正频率，同时保持当前物理车速、15 秒试验时长和时间型安全保护不变。

## 范围

`empty.syscfg` 中的 `TIMER_CONTROL` 是唯一控制节拍来源。将其周期设为 `6.667 ms` 并通过既有 SysConfig CLI 生成 `syscfg_gen/`。不手改任何生成文件，也不改变引脚、时钟源、PWM 或通信硬件配置。

速度量均改为“每 6.667 ms 编码器计数”。手动参数按时间基准换算：基础速度 40→27，速度和差速上限 100→67，速度 Kp 8→12，左右前馈 28→42、23→34.5。Ki 继续为 0。

循线输出也使用新的速度单位：线 Kp 从 `Q16_ONE / 56` 改为 `Q16_ONE / 84`；线 Kd 保持 `Q16_ONE / 448`，因为误差差分和速度单位均按相同的 2/3 比例变化。D 滤波历史系数从 1/2 调为 5/8 以维持近似相同的物理滤波时间；D 原始差分限幅从 3500 调为 2333。

## 保持的行为

- 丢线保护仍约 150 ms：15→23 tick。
- 堵转保护仍约 300 ms：30→45 tick。
- 控制超期的近似时间阈值由 3→5 tick。
- 试验仍为 15 秒：1500→2250 tick。
- 遥测实际频率不变，间隔计算基数从 100 改为 150。

## 移除通信超时

彻底移除蓝牙心跳/通信超时停车：不再保留通信超时 tick 常量、最近有效帧时间、心跳刷新 API、`requireCommHeartbeat` 参数及其安全判定；协议收帧不再通知试验管理器。相应删除通信超时的停止原因和故障码，以及仅为该保护存在的 host 测试。蓝牙仍可按既有协议启动、停止和查询试验；本地丢线、堵转、参数错误和控制超期保护不受影响。

## 验证

运行既有手动调参和试验时长脚本、host 测试及 `git diff --check`。使用 SysConfig CLI 重新生成后构建 Debug 工程。硬件验证只由用户烧录后完成；首次实车仍应先悬空确认方向与无堵转。
